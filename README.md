# RoleLoop_Features

用于 RoleLoop 论文绘图的数据、代码与图件协作仓库。这里把原始实验结果提取出的 CSV、数据处理过程、绘图代码、绘图说明和最终图片放在一起，使每张图的数据可追溯、样式可修改、结果可复现。

**核心约定：一张图对应一个独立文件夹；新增数据、修改代码、更新图件和说明应保持同步。**

当前仓库包含规范、空白模板，以及 [RoleLoop 交互与 token 开销的数据交接包](figures/fig_001_interaction_efficiency/README.md)（`data-ready`）。该包仅含作者提供的汇总数据与处理流程，图件交由合作者生成；尚无独立复现或论文成品图。模板中的待填写项不代表已完成的实验或验证。

## 1. 目录结构

```text
RoleLoop_Features/
├── README.md                       # 项目规则与协作入口
├── LICENSE                         # 原创代码与文档的 MIT 许可证
├── figures/
│   ├── README.md                   # 全部图件的统一索引
│   └── fig_001_performance/         # 示例名称；创建后才存在
│       ├── README.md               # 图件介绍、负责人、状态、快速复现入口
│       ├── data/
│       │   ├── raw/                # 从原始实验结果提取的 CSV
│       │   ├── processed/          # 清洗、聚合、统计后用于绘图的 CSV
│       │   ├── sources.csv         # 输入文件与实验来源的对应清单
│       │   └── LICENSE.md          # 本图数据的来源与使用许可
│       ├── code/                   # 提取、处理、绘图脚本
│       ├── config/                 # 图表样式、筛选条件和统计配置
│       ├── docs/
│       │   ├── provenance.md       # 数据来源与提取过程
│       │   ├── data_dictionary.csv # CSV 字段含义、单位与缺失值约定
│       │   ├── plot_spec.md        # 绘图需求、视觉规范与图注
│       │   ├── reproduction.md     # 环境、完整命令、输出与验证记录
│       │   └── CHANGELOG.md        # 数据与图件修改记录
│       ├── images/                # 最终 PDF / SVG、PNG 预览及生成清单
│       │   └── manifest.csv
│       └── requirements.txt       # 本图经验证的 Python 依赖版本
├── templates/figure/               # 单图空白模板
├── scripts/new_figure.py            # 按模板建立单图文件夹
└── .github/                        # 提问、数据补充和 PR 模板
```

每个多面板图的所有面板放在同一个图文件夹；独立编号的图分别建文件夹。全仓库以 [图件索引](figures/README.md) 统一展示标题、状态、负责人、说明和预览。

## 2. 快速开始

克隆仓库，然后在仓库根目录执行以下命令。创建模板仅需要 Python 3.9 或更高版本，无第三方依赖。

```bash
git clone https://github.com/bbbdbbb/RoleLoop_Features.git
cd RoleLoop_Features
python scripts/new_figure.py fig_001_performance
```

`fig_001_performance` 是示例名称，请使用未占用的编号与具体主题。脚本会创建文件夹和说明模板，拒绝覆盖已有目录；它不会生成实验数据、绘图程序或成品图片。

创建后按顺序完成：

1. 填写新目录的 `README.md`，说明图的目的、论文位置、负责人和状态，并更新 `figures/README.md` 索引。
2. 将提取的 CSV 放入 `data/raw/`，填写 `data/sources.csv`、数据字典和来源说明。
3. 在 `code/` 中实现数据处理和绘图，在 `config/` 中保存影响结果的参数。
4. 记录实际运行环境、依赖版本和可复制执行的命令，生成 `data/processed/` 与 `images/`。
5. 将图件 PNG 预览嵌入本图 `README.md`，更新索引预览链接，再通过 PR 提交完整变更。

模板里的 `requirements.txt` 初始只有说明。依赖和绘图入口由每张图的作者补齐，不能把模板直接当作已经可以复现的绘图项目。

## 3. 图件命名与状态

- 目录格式为 `fig_<三位编号>_<英文主题>`，例如 `fig_001_performance`、`fig_002_ablation`；主题使用小写字母、数字和下划线。
- 编号在本仓库中保持稳定。论文图号变化时更新说明中的对应关系，不必重命名整个目录。
- 同一张图的新数据、新样式和修订版本在原目录中维护，通过 Git 和 `docs/CHANGELOG.md` 记录，不另建 `final_final_v2` 等目录。
- 多面板图可在文件名中使用 `panel_a`、`panel_b`，整体成品使用一致的图件 ID。

| 状态 | 含义 |
| --- | --- |
| `planned` | 已确定绘图问题，数据或实现尚未齐备 |
| `data-ready` | 数据、字段、来源及提取说明已齐备 |
| `draft` | 已生成草图，等待核对或修订 |
| `reproduced` | 他人在独立环境运行成功，并记录环境、版本和验证结果 |
| `paper-ready` | 作者核对数据、图注及排版后确认可用于论文 |

状态是实际完成情况的记录。单纯上传代码或图片不表示已经复现成功。

## 4. CSV 数据规范

### 原始提取数据与处理后数据

- `data/raw/` 保存从实验日志、结果 JSON、评测输出或其他可核对来源提取的 CSV。它是绘图的原始输入，不要求把大型训练日志或完整数据集复制进来。
- 原始 CSV 保留来源中的数值和精度。筛选、归一化、单位换算、聚合、排序及缺失值处理在代码中完成，结果写入 `data/processed/`。
- 提取也应尽量脚本化。若只能人工转录，必须注明来源位置、转录规则和核对方式，不能声称已经复现原始提取过程。
- 发现原始数据有误时保留修订依据，在 Git 提交与变更记录中说明旧值、修正值及影响的图件，不悄悄替换结果。
- 不猜测填补缺失实验，不将演示数据、历史算法结果或待完成项目写成当前已测结果。确需演示数据时单独命名并显著标注 `synthetic`，不得混入论文结果。

### 文件与字段

- CSV 使用 UTF-8、逗号分隔和首行字段名；文本文件使用 LF 换行。字段名采用 `snake_case`，文件名清晰表达实验或数据版本。
- 一行的统计粒度必须明确，例如一次运行、一个样本或一个聚合点。长表格式优先，但不强制所有图使用相同字段。
- 为每个 CSV 的每个字段填写 `docs/data_dictionary.csv`：类型、含义、单位、允许值、缺失值表示和是否必填。
- 有重复实验时保留实际 `run_id`、`seed` 或其他运行标识。它们不存在时说明原因，不自行编造。
- 需要区分百分数 `0–100` 与比例 `0–1`，标明时间、显存、长度等单位；跨数据文件保持一致或记录转换过程。
- 缺失值统一使用空单元格或明确约定的标记，并写入数据字典；不能用 `0` 冒充缺失值。
- 声明主键或唯一性规则，核对重复行、样本数量和有效范围。保留未四舍五入的数值，展示精度由绘图代码控制。
- 均值、中位数、标准差、标准误和置信区间不能混用；必须记录样本数、聚合层级、公式及误差条含义。

### 来源记录

`data/sources.csv` 以仓库根目录为相对路径基准，至少为每个原始 CSV 记录来源。一个文件来自多个实验时可有多行，必要时在 CSV 中保留 `source_id` 建立逐行映射。

| 字段 | 说明 |
| --- | --- |
| `source_id` | 本图内稳定的来源标识；若对应多行，需说明映射规则 |
| `file_path` | 该来源生成的原始 CSV 的仓库相对路径 |
| `origin_uri` | 原始结果的可核对位置、下载地址或公开存档标识 |
| `experiment_id` / `run_id` | 实验与运行标识，未知时留空并解释 |
| `source_revision` | 实验代码 commit、结果发布版本或其他稳定版本 |
| `source_sha256` | 可获取的原始源文件校验值；不可获取时在说明中记录原因 |
| `csv_sha256` | 提取后的原始 CSV 的 SHA-256 |
| `extraction_command` | 提取命令；复杂流程可指向 `docs/provenance.md` |
| `notes` | 时间、筛选范围、人工步骤、访问限制等补充说明 |

仅有“来自某次实验”或个人机器上的绝对路径不足以支持公开复现。无法公开原始日志时写清限制，并提供允许发布的最小绘图输入；区分“从提供的 CSV 重画图”与“重新运行实验得到这些结果”。

## 5. 绘图代码、说明与图片

- `code/` 保存提取、处理和绘图代码；按需提供 `extract_data.py`、`prepare_data.py`、`plot.py`，不需要的步骤可以省略并说明。
- 路径基于仓库或图件目录解析，不能依赖作者电脑的盘符。记录每条命令的工作目录，做到另一位作者可以直接照着执行。
- 绘图读取 CSV 和配置；实验数值不直接写死在画图脚本中。颜色、字体、图尺寸等可以集中放入 `config/`。
- 固定会影响结果的随机种子，记录 Python / R / MATLAB 等实际工具版本，以及字体和系统依赖。Python 项目锁定实际验证过的依赖版本；其他语言可替换依赖文件，但必须在说明中给出安装方式。
- Notebook 可以用于探索；最终必须提供可从头执行的流程，避免依赖未保存的内存变量、手工点击或单元格执行顺序。
- `docs/plot_spec.md` 写明图要回答的问题、各面板、坐标轴、单位、刻度、图例、颜色、误差条、尺寸、图注和已知限制。
- `images/` 保存论文可用的 PDF / SVG 等输出，以及便于 GitHub 查看效果的 PNG 预览。适用时优先提供矢量图，栅格图说明分辨率和用途。
- 多种导出格式来自同一套代码与配置。必须人工后处理时保留可编辑源文件、具体步骤，并说明自动复现边界。
- `images/manifest.csv` 记录输出路径、UTC 生成时间、代码 commit、输入数据版本、命令及输出 SHA-256。代码和数据应先有可识别版本，随后提交生成图件与验证记录，避免用尚不存在的提交号自指。

## 6. 复现验收

每张图在 `docs/reproduction.md` 中提供完整步骤，而不是只写“运行脚本”。至少包含：

1. 输入数据文件及其版本、校验值、获取方式。
2. 已验证的操作系统、运行时、依赖安装命令及字体等额外要求。
3. 从原始 CSV 到处理后 CSV，再到所有图件输出的完整命令与工作目录。
4. 预期输出路径，以及行数、样本数、关键统计值、面板数量等核对方法。
5. 最近验证者、日期、代码与数据版本、实际执行结果及仍未解决的问题。

他人从干净克隆和独立环境运行成功后，才将状态更新为 `reproduced`。比较数值和图形内容时说明容差；PDF 元数据或字体环境导致的文件哈希不同，不自动等于实验结果不同。文件校验值用于识别版本，不能代替内容核对。

## 7. 提问题与补充数据

### 绘图作者提问

通过 [Issues](https://github.com/bbbdbbb/RoleLoop_Features/issues/new/choose) 使用“绘图问题 / 复现问题”模板，提供图件 ID、文件和字段、当前版本、预期结果、实际结果以及报错或截图。缺少数据或不清楚指标含义时先提出明确问题，不自行猜测。

### 新数据与修改请求

补充数据可以先创建“数据补充 / 修正” Issue，再通过分支或 Fork 提交 PR；简单且证据齐全的修改也可直接提 PR。

1. 说明关联图件、新增实验条件、数据来源以及要解决的问题。
2. 将新数据放入对应图目录，补齐来源清单、数据字典、许可及必要的提取代码。
3. 更新处理和绘图代码，重新生成受影响的图件；若数据尚未齐备或无法重画，明确标为草稿并列出待办。
4. 更新本图说明、变更记录和总索引，并记录此次复现命令与验证结果。
5. PR 说明哪些数据和图件发生变化、数值或图形为何改变、如何验证；关联已有 Issue。

不同数据集或不同实验条件不能只因为列名相同就直接合并。先核对评测协议、指标定义、单位、样本粒度和运行版本；存在差异时保留区分字段并明确可比范围。

## 8. 数据存储与许可证

本仓库主要保存可公开的绘图 CSV、代码、说明与必要图件。体积较大的原始日志、模型权重或数据集优先保留稳定外部地址、版本、校验值与下载步骤，不作为一般 Git 文件反复提交。采用 Git LFS 或其他存储方式前说明获取流程，确保其他作者可实际取得输入。

GitHub 对普通 Git 文件大于 50 MiB 给出警告，并阻止大于 100 MiB 的文件；有关限制以 [GitHub 官方说明](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github) 为准。

仓库原创代码与文档采用 [MIT License](LICENSE)。数据及基于数据生成的图件应在各图的 `data/LICENSE.md` 中单独明确可用许可、来源署名及上游限制；根目录 MIT 许可不自动重新授权第三方数据。初始模板不包含实际数据授权，提交真实数据前必须填写适用条款，并保留需要的第三方声明。

仅提交有权公开的内容。凭据、个人隐私及未经授权公开的实验材料不进入公开仓库。

- [ ] 提取、处理和绘图流程可追溯；无未经说明的手工改数或演示数据混入。
